# Enterprise RAG

A production-ready Retrieval-Augmented Generation (RAG) system that lets you upload enterprise documents and chat with them using a local LLM. Ships as a self-contained Docker product you can deliver to clients.

---

## What It Does

- **Admin** uploads PDF, DOCX, PPTX, or TXT files via a web panel
- Documents are parsed, chunked, embedded (BGE-M3), and stored in Qdrant
- **Users** chat with the documents through an embeddable widget on any website
- Answers are generated by a local LLM (LM Studio) — grounded in your documents
- Optional **lead capture** form collects Name, Phone, Email before users can chat

---

## Architecture

```
Browser (Widget)
      │
      ▼
 FastAPI (port 8010)
      │
      ├── Qdrant (vector DB)  — stores document embeddings
      ├── LM Studio           — generates answers (runs on your machine/LAN)
      └── BGE-M3 + Reranker   — embedding + reranking models
```

Two Docker containers:
- `rag-api` — FastAPI app with all ML models loaded
- `rag-qdrant` — Qdrant vector database

## Quick Start (Development)

### 1. Prerequisites
- Docker Desktop (8 GB RAM allocated — Settings → Resources → Memory)
- LM Studio running on your machine with a model loaded
- In LM Studio: Settings → enable **"Listen on local network"**

### 2. Clone and configure
```bash
git clone https://github.com/your-repo/enterprise-rag.git
cd enterprise-rag

cp .env.example .env
```

Edit `.env`:
```env
LMSTUDIO_BASE_URL=http://host.docker.internal:1234
LMSTUDIO_MODEL=your-model-name

ADMIN_USERNAME=admin
ADMIN_PASSWORD=your_strong_password

# Generate this:  python3 -c "import secrets; print(secrets.token_hex(32))"
JWT_SECRET=paste_generated_secret_here

COLLECT_USER_DETAILS=false
```

### 3. Build and run
```bash
docker compose build --no-cache
docker compose up -d
```

First startup downloads BGE-M3 and the reranker model (~3 GB). This takes 5–10 minutes once. Subsequent starts are instant (cached in Docker volume).

### 4. Open the admin panel
```
http://localhost:8010/static/index.html
```

## Admin Panel

Login with your `ADMIN_USERNAME` / `ADMIN_PASSWORD`.

| Tab | What it does |
|-----|-------------|
| **Chat** | Test the RAG chatbot directly |
| **Upload Docs** | Upload PDF, DOCX, PPTX, TXT (max 50 MB) |
| **Documents** | View and delete indexed documents |
| **Leads** | View and export captured user contacts as CSV |

## Embedding the Widget on Any Website

Add these two lines before `</body>` on any HTML page:

```html
<script>
  window.RAG_CONFIG = {
    serverUrl: "http://YOUR-SERVER-IP:8010",
    title: "AI Assistant",
    theme: "#4F46E5"
  };
</script>
<script src="http://YOUR-SERVER-IP:8010/static/widget.js"></script>
```

That's it. The chat bubble appears bottom-right on your site.

### Lead Capture Toggle
To collect user details (Name, Phone, Email) before they can chat:
```env
# .env
COLLECT_USER_DETAILS=true
```
Then restart:
```bash
docker compose restart rag-api
```
No rebuild needed. Captured leads appear in the **Leads** tab of the admin panel and can be exported as CSV.

## Configuration Reference (`.env`)

| Variable | Required | Description |
|----------|----------|-------------|
| `QDRANT_URL` | Yes | Leave as `http://qdrant:6333` |
| `LMSTUDIO_BASE_URL` | Yes | IP of the machine running LM Studio |
| `LMSTUDIO_MODEL` | Yes | Model name as shown in LM Studio |
| `ADMIN_USERNAME` | Yes | Admin login username |
| `ADMIN_PASSWORD` | Yes | Admin login password |
| `JWT_SECRET` | Yes | Random secret for JWT signing |
| `COLLECT_USER_DETAILS` | No | `true` / `false` (default: `false`) |
| `MAX_FILE_SIZE_MB` | No | Max upload size in MB (default: `50`) |

## Delivering to a Client

### Step 1 — Build and push your image (you do this once)
```bash
docker build -t your-dockerhub/enterprise-rag:v1.0 .
docker push your-dockerhub/enterprise-rag:v1.0
```

### Step 2 — Update docker-compose.yml
Change the `build: .` line to:
```yaml
image: your-dockerhub/enterprise-rag:v1.0
```

### Step 3 — Give the client these 3 files only
```
docker-compose.yml
.env.example        ← they rename to .env and fill in their values
README.md
```
No source code is exposed. The client runs `docker compose up -d` and everything starts.

### Step 4 — Client's LM Studio setup
If LM Studio runs on a **different machine** than the Docker containers:

1. Open LM Studio on that machine
2. Settings → enable **"Listen on local network"**
3. Note the IP address shown (e.g. `192.168.1.50`)
4. Set in `.env`: `LMSTUDIO_BASE_URL=http://192.168.1.50:1234`
5. Restart: `docker compose restart rag-api`

If LM Studio is on the **same machine** as Docker:
```env
LMSTUDIO_BASE_URL=http://host.docker.internal:1234
```

## Data & Persistence

| What | Where | Notes |
|------|-------|-------|
| Document vectors | `./qdrant_storage/` | Persists across restarts |
| Captured leads | `./uploads/leads.json` | Persists across restarts |
| HuggingFace models | Docker volume `hf_cache` | Downloaded once |
| Uploaded files | Deleted after indexing | Not stored permanently |

To start completely fresh:
```bash
docker compose down
rm -rf qdrant_storage uploads
docker compose up -d
```

## Troubleshooting

**Container keeps restarting / exit code 137**
→ Docker ran out of memory. Increase Docker Desktop RAM to 8 GB.
→ Docker Desktop → Settings → Resources → Memory → 8 GB

**LM Studio not responding**
→ Ensure "Listen on local network" is enabled in LM Studio settings.
→ Check the IP in `LMSTUDIO_BASE_URL` matches your LM Studio machine.
→ Ensure the model is loaded and running in LM Studio.

**Widget not showing on my site**
→ If your site is HTTPS, the `serverUrl` in `RAG_CONFIG` must also be HTTPS.
→ Put the RAG API behind Nginx with a Let's Encrypt SSL certificate.

**File upload failing**
→ Check file is under `MAX_FILE_SIZE_MB` (default 50 MB).
→ Supported formats: PDF, DOCX, PPTX, TXT only.
→ Scanned / image-only PDFs cannot be parsed (no OCR).

**First startup is very slow**
→ Normal — BGE-M3 and the reranker (~3 GB total) are downloading.
→ Check progress: `docker compose logs -f rag-api`

## API Endpoints

| Method | Endpoint | Auth | Description |
|--------|----------|------|-------------|
| GET | `/health` | None | Health check |
| GET | `/widget-config` | None | Widget feature flags |
